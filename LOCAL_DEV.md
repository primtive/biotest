# Локальное окружение для проверок

Сайт: http://localhost:3001. Next.js работает на хосте, MongoDB 4.4.6 — в отдельном Docker Compose проекте `biotest-local`.

MongoDB доступна только локально на `127.0.0.1:27018`. Данные сохраняются в volume `biotest-local_mongo_data`. Контейнеры и volumes прежнего окружения `biotest` не используются.

## Повторный запуск

Запустить Docker Desktop, затем из корня проекта:

```sh
docker compose -f compose.local.yml up -d
npm run dev:local
```

Сервис `mongo-init` настраивает одноузловой replica set `rs0`; повторный запуск сохраняет существующую конфигурацию и данные. Статус `Exited (0)` для `mongo-init` нормален.

Настройки приложения находятся в игнорируемом `.env.local`: `DATABASE_URL`, `NEXTAUTH_URL` и локальный `NEXTAUTH_SECRET`. Исходный `.env` сохранён.

`dev:local` использует webpack. Шрифты включены в проект: запуск и сборка не требуют доступа к Google Fonts. Обычный `npm run dev` использует Turbopack.

## Восстановление дампа в пустое окружение

Требуется `mongorestore` из MongoDB Database Tools. После запуска MongoDB и выбора primary:

```sh
mongorestore \
  --uri='mongodb://127.0.0.1:27018/biotest?replicaSet=rs0&directConnection=true' \
  --stopOnError \
  --dir='/Users/alexey/other/dumps/biotest-dump-30.05.26/biotest'
```

Восстановление выполняется один раз в пустую базу. Начальные количества: User — 302, Test — 13 369, Task — 6 020, Topic — 93, TopicGroup — 2, UserTopicProgress — 4 338.

Для сохранения исходного состояния дампа `prisma db push` не запускается. Вход теперь требует логин и пароль. В старом дампе паролей нет, поэтому прежний вход по одному логину отключён; старые сессии также недействительны.

## Исправление данных и выдача паролей

Предварительная проверка без записи:

```sh
npm run db:repair
```

Перед применением остановить приложение и другие процессы записи в эту базу. Применение выполняется отдельным явным шагом. Скрипт сначала сохраняет `mongodump` в `.local/before-repair-*.archive`, затем устраняет дубликаты логинов и ответов, пересчитывает результаты и прогресс, дополняет снимки старых заданий с сохранением уже записанных редакций и создаёт индексы. При прерывании повторный запуск завершает пересчёт; резервная копия позволяет вернуть исходное состояние:

```sh
npm run db:repair -- --apply
npm run accounts:local
```

В этом сеансе эти две команды ещё не применены: автоматическая проверка разрешений отклонила массовое изменение базы и создание постоянных аккаунтов. Для их выполнения ожидается отдельное разрешение пользователя.

`accounts:local` создаёт либо обновляет `local-admin` и `local-student` только в локальной базе. Случайные пароли сохраняются в `.local/credentials.json` с правами `0600`; каталог исключён из Git и Docker. Повторный запуск меняет пароли и отзывает предыдущие сессии. Для выдачи пароля существующему пользователю `node scripts/accounts.cjs` принимает JSON с `username` и `password` через stdin. Пароль не следует передавать аргументом командной строки.

Снимки старых тестов восстанавливаются из текущего содержимого дампа с пометкой `legacy-import`: первоначальные редакции утраченных заданий восстановить невозможно. Новые попытки сразу сохраняют собственный снимок задания.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:integration
npm run test:migration
```

Интеграционные проверки требуют работающего сайта на `localhost:3001` и локальной MongoDB с replica set. Они создают собственные временные записи `rt-reg-*`, удаляют их в `finally` и сохраняют обезличенный результат в `.local/integration-results.json`. Исходные записи дампа не изменяются. Исторический отчёт до исправлений находится в `runtime-review/REVIEW.md`; его старые сценарии воспроизведения не заменяют регрессионные тесты.

`test:migration` создаёт отдельную синтетическую базу `biotest_repair_test_*`, дважды применяет скрипт исправления, проверяет повторяемость результата, индексы и сохранение ручных начислений и старых снимков. После проверки эта база и только её резервные копии удаляются. Основная база не меняется.

Старые импортёры не запускаются приложением. `parser1` требует явный `TOPIC_GROUP_ID` существующей группы и добавляет темы только в неё. Импорт FIPI больше не удаляет существующие задания; он отключён до явного `ALLOW_LEGACY_IMPORT=1`. Формат внешних сайтов в этом сеансе не проверялся.

## Остановка

Остановить Next.js через Ctrl+C, затем:

```sh
docker compose -f compose.local.yml down
```

Команда сохраняет volume с базой. Для дальнейших проверок можно продолжать использовать эту копию данных.
